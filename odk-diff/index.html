    Systematic Comparison of RXNO Before and After the ODK Migration

    author: Philip Strömert | author: Noura Rayya | created on: 06.10.2026

    Pre-ODK Migration Background

    Before the migration to an Ontology Development Kit (ODK) based workflow, the two ontologies RXNO and MOP were maintained within the same GitHub repository: https://github.com/rsc-ontology/rxno. Their release workflow relied on editing the release files rxno.owland mop.owl directly in Protégé and then converting them to OBO format with ROBOT. Hence, these files were the source of truth for both ontologies, which is in contrast to an ODK-based workflow, where release files in different serialisation formats are generated automatically from a separate editor OWL file and/or component files (OWL files and/or ROBOT TSV files).

    In 2021, as a result of the Ontologies4Chem: the landscape of ontologies in chemistry overview paper, the NFDI4Chem team began improving both ontologies by filing issues and pull requests in this single RXNO repository. One of the first suggestions was to properly import MOP into RXNO using owl:import instead of (re)defining the MOP classes within the rxno.owl file (see issue #27). While trying to resolve this issue in 2022, more issues were identified in the MOP side, which are described in more detail in the MOP ODK migration documentation.

    ODK Migration Background

    All issues preventing a proper import of MOP into RXNO have since been resolved with the migration of RXNO and MOP to ODK-based repositories. As part of this, all RXNO terms and axioms defined in the pre-ODK RXNO release version were copied into the ODK-based RXNO editor file, from which different release artifacts were then generated automatically with standard ODK commands.

    Creating and Archiving a Pre-ODK Release of RXNO and MOP

    Before the migration to ODK, both ontologies were published only directly in the GitHub repository's code base; no GitHub releases had ever been created. We therefore created a pre-ODK release and tag so that these versions of RXNO and MOP could be referenced properly: https://github.com/rsc-ontology/rxno/tree/pre-odk-release .

    Creating ROBOT diff Comparing RXNO Before and After the ODK Migration

    We used ROBOT to generate a diff between the pre and post ODK RXNO release versions, to make sure the ODK migration did not produce any unaccounted changes of RXNO. These are the steps and commands we used for generating this diff:

    1. Download the pre-ODK RXNO file rxno_pre_odk.owl 
      curl -o rxno_pre_odk.owl https://raw.githubusercontent.com/rsc-ontology/rxno/refs/tags/pre-odk-release/rxno.owl

    2. Generate a base release from the previously downloaded pre-ODK RXNO version rxno_base_pre_odk.owl that only contains the RXNO classes and just references all external ontology terms via their PURL: 

      robot remove -i rxno_pre_odk.owl --base-iri RXNO --exclude-term owl:versionIRI --axioms external --preserve-structure false --trim false -o rxno_base_pre_odk.owl
      This step is necessary to produce a slimmer diff later, as it excludes any axioms and annotations asserted on imported external terms.

    3. Download the base release of the post-ODK RXNO version rxno_base_post_odk.owl shell curl -o rxno_base_post_odk.owl https://raw.githubusercontent.com/rsc-ontology/rxno/refs/tags/v2026-10-29/rxno-base.owl

    4. Produce the diff to see the changes after the ODK migration in HTML (rxno_pre_vs_post_odk_diff.html) and Markdown format (rxno_pre_vs_post_odk_diff.md): 
      robot diff --left rxno_base_pre_odk.owl --right rxno_base_post_odk.owl  \
      -f html -o rxno_pre_vs_post_odk_diff.html &&
robot diff --left rxno_base_pre_odk.owl --right rxno_base_post_odk.owl  \
      -f markdown -o rxno_pre_vs_post_odk_diff.md

    Analysing ROBOT diff Comparing RXNO Before and After the ODK Migration

    Pipeline Artifact

    Removal or Addition of External Terms

    Cause: The diff compares two OWL files that each contain only the axioms relevant to RXNO terms. An external term (from BFO, COB, IAO, MOP, OBI, RO, etc.) is declared in one file but not the other depending on whether it is referenced in an axiom on a RXNO term in that specific file.

    Action: Ignore. The axiom difference is the semantic issue (covered under Semantic Changes below); the presence of the external term declaration is a pipeline artifact associated with the OWL syntax.

    Removed external terms (11): BFO_0000057, BFO_0000077, BFO_0000078, MOP_0000713, MOP_0000714, MOP_0000715, OBI_0000011, http://purl.org/dc/elements/1.1/creator, http://purl.org/dc/elements/1.1/date, http://purl.org/dc/elements/1.1/description, http://purl.org/dc/elements/1.1/title

    Added external terms (17): COB_0000035, COB_0000082, MOP_0000591, MOP_0000629, MOP_0000708, MOP_0006370, MOP_0006371, RO_0000057, RO_0004008, RO_0004009, http://purl.org/dc/terms/contributor, http://purl.org/dc/terms/creator, http://purl.org/dc/terms/date, http://purl.org/dc/terms/description, http://purl.org/dc/terms/title, http://purl.org/dc/elements/1.1/type

    Deletion of Inherited SubClassOf Axioms

    Cause: Because we compare release versions, the file generated automatically by ODK from the RXNO editor file differs from the pre‑ODK one, owing to the ROBOT reduce step in the ODK release build pipeline. For example if an axiom is asserted on an RXNO term in the editor file (e.g., 'has specified product' some olefin on 'Horner reaction') but the same axiom is already present on the parent of this term (e.g., olefination), the ROBOT reduce step will delete this axiom from the child, as it is already inherited by the parent (see 'Horner reaction' in the RXNO release versus the editor file.)

    Action: TODO: Delete these redundant axioms from the terms in the RXNO editor file (issue #76)

    Semantic Changes

    Replacement of BFO with RO Relations

    Cause: In the axiomatization of RXNO terms, BFO relations, such as BFO_0000057 # has_participant, were used that are not supported by the BFO classes only version used in the OBO Foundry. According to the OBO Foundry principle 7 relations defined in the Relations Ontology (RO) should be used whenever possible, which is the case for such high level BFO relations.

    Action: In the ODK migration these BFO relations were replaced with suitable RO equivalents in PR#68. Here is the list of terms and IRIs were this change took place, along with the affected classes:

    Resynchronization After MOP Disentanglement

    Cause: Before the ODK migration, RXNO used wrong IDs for some MOP classes that were used as parents for RXNO classes, e.g. MOP_0000713 was used for carboxylation, whereas MOP_0000591 is the correct ID in MOP. For more details, check MOP ODM migration docs: Critical Severity: IRI clashes - One IRI, two different reactions.

    Action: Those RXNO classes got their subClassOf axioms updated.

    Affected terms (7): - Kolbe-Schmitt reaction http://purl.obolibrary.org/obo/RXNO_0000182 - Lemieux-Johnson oxidation http://purl.obolibrary.org/obo/RXNO_0000649 - Criegee oxidation http://purl.obolibrary.org/obo/RXNO_0000257 - Malaprade reaction http://purl.obolibrary.org/obo/RXNO_0000650 - alkyne-azide click reaction http://purl.obolibrary.org/obo/RXNO_0000269 - copper(I)-catalyzed azide-alkyne cycloaddition http://purl.obolibrary.org/obo/RXNO_0000270 - Seyferth-Gilbert homologation http://purl.obolibrary.org/obo/RXNO_0000387

    COB Dependency Adoption

    Cause: With the 2025-12-18 Release, the Ontology for Biomedical Investigations (OBI) started using the BFO-aligned Core Ontology for Biology and Biomedicine (COB) as their top-level ontology. This change included the deprecation of some of their terms in favor of COB terms. Since RXNO reused the now deprecated planned process OBI_0000011, all relevant axioms had to be updated to point to its COB replacement: completely executed planned process COB_0000035.

    Affected terms: (2)

    • planned reaction step http://purl.obolibrary.org/obo/RXNO_0000001
    • planned synthesis http://purl.obolibrary.org/obo/RXNO_0000329

    Metadata Changes

    Ontology Annotation Changes

    The ontology annotations of RXNO were updated in the course of the ODK migration. This included switching from using DC Elements predicates to DC Terms ones for title and description (see https://github.com/rsc-ontology/rxno/pull/74), adding Colin Batchelor and the NFDI4Chem team as contributors and using the owl:versionInfo autogenerated by ODK. The fact that we are also comparing base releases (versions that only declare external terms but not further define them), explains also the additional DC Elements type annotation. It is added automatically by ODK for any base release, whereas it was not added for the pre-ODK RXNO version, because we manually created this base release with ROBOT.

    Classes Annotations Changes

    The two annotations properties dc11:creator and dc11:date were removed and instead, the annotations properties dcterms:creator and dcterms:date were added respectively. This was done in the PR: Update from using the deprecated DC Elements to using the recommended DC Terms - #74
